# AXIO 노이즈 테스트

NEXT AXIO와 Stagetec RIF67의 AES67 송신 스트림에서 나타나는 **주기적인 오디오 이상(글리치)** 을 확인한 시험 기록입니다. 2026-11-12 ~ 2026-11-18, 사무실(본사)에서 진행했습니다.

> 개인 시험 기록입니다. 제조사(Stagetec, 장비 제조사)의 확인을 받지 않았고, 원인은 가설입니다.

## 요약

| 시험 | 구성 | 결과 |
|---|---|---|
| 11/12 | AVATUS → NEXUS/RIF67 → AES67 → AXIO(AES67 모드) → 아날로그 → M32 녹음 | 글리치 96회(10분), 약 6.2초 간격 |
| 11/12 | AXIO 스탠드얼론 → 아날로그 → M32 | 글리치 없음 |
| 11/17 | AXIO **Dante 모드** ↔ NEXUS XDIP 카드 → M32 (재부팅 포함) | 글리치 **0회** |
| 11/17 | AXIO **AES67 모드** → M32 | 글리치 91회(6분), 약 4초 간격 |
| 11/18 | AXIO 한 대 + 맥(직결), 제너레이터 스트림을 맥이 수신 | 글리치 520회(10분), 간격 1.4초 → 1.04초로 감소 |
| 11/18 | 위와 같음, 제너레이터와 M32 사인파 두 스트림 동시 수신 | **두 스트림 모두 646회, 평균 간격 0.925초, 이벤트 시각 0.2ms 이내 일치** |
| 11/18 | RIF67 직결, 1kHz 톤 | 글리치 15회(9분 8초), 평균 간격 36초 |

- 글리치는 패킷 번호 빠짐 없이, 패킷 안의 **샘플이 약 1~4ms 동안 섞이는** 형태입니다(0으로 끊기는 것이 아님).
- AXIO를 **Dante 모드로 쓰면** 같은 장비, 같은 M32, 같은 톤에서 나타나지 않았습니다.
- AXIO 단독(다른 장비 없음)에서 재현되고, 서로 다른 소스(내부 제너레이터, 아날로그 입력)의 스트림에 **같은 순간** 나타납니다.
- 발생 간격은 두 내부 클럭의 차이(약 0.3~11ppm)와 맞아서, AES67 송신 단계의 클럭 보정 동작이 의심됩니다(**가설**).

## 도구

- `aes67_rx_wav.py` : AES67(RTP L24) 멀티캐스트를 받아 WAV로 저장하고 패킷 번호/타임스탬프를 검사합니다(파이썬 표준 라이브러리만 사용).
  ```
  python3 aes67_rx_wav.py --iface-ip <맥IP> --group 239.1.0.1 --port 5004 --channels 8 --fs 96000 --spp 48 --save 1,2 --minutes 10
  ```
  - `--fs`, `--spp`, `--channels`는 스트림 설정(SDP)에 맞춰 직접 입력합니다(스트림에서 읽지 않음).
  - 합성 사인파로 비트 단위 정확성을 확인했습니다(저장된 샘플이 정답과 불일치 0).
- `an96.c` : 96kHz 24bit 사인파 WAV에서 글리치를 찾는 분석 도구(점화식 잔차 방식, C).
  ```
  cc -O2 an96.c -o an96 -lm && ./an96 file.wav 96000 2
  ```
- `hf96.c` : 사인파가 아닌 신호에서 고주파 성분이 튀는 구간을 찾는 보조 도구.
